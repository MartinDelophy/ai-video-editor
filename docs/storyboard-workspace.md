# Storyboard workspace

Workflow → Storyboard opens a separately loaded, full-window ChatCut + node canvas. A new conversation starts with an empty dotted canvas. Uploading an image creates a real reference node. Dialogue can create character/environment sheets and one complete 4×4 storyboard image. Nodes have semantic reference edges, draggable positions, pan, zoom and fit controls; original images open in the shared media preview.

The two supplied images are internal production generation guides: `public/assets/storyboard/default-character.png` and `public/assets/storyboard/default-planning-board.png`. Both are loaded lazily and passed as actual reference-image bytes for image generation. They never enter My assets, conversation attachments, @ suggestions or canvas nodes. Character-sheet structure and cinematic planning-board layout guide the output; user intent and user-provided characters take precedence. Guide watermarks, identity text and the example's eight-shot count are not copied: the storyboard remains one 4×4 image. Generated files use the shared Anna transport adapter, retain actual provider/model receipts, enter My assets, and never enter the timeline automatically. The image selector lists actual image-generation models from the host catalog. The verified catalog has Gemini 2.5 Flash Image and GPT Image 2, but no model named GPT Image 2.5 Flash. GPT Image 2 (fal), `openai/gpt-image-2`, is the user-confirmed current default when available; an unavailable selection fails before generation. Reference assets are uploaded through the host files API and sent as `reference_image_urls`.

The conversation model selector supports Anna default, catalog-advertised chat models, and a user-entered enabled model name. `llm.complete` only exposes routing preferences, so selection passes `modelPreferences.hints[0].name`; the UI also shows the actual returned model. A turn captures its selected chat and image models once; changing them affects the next turn and preserves history. If the returned chat model differs from an explicitly requested model, the turn stops before any generation. The real bridge consumes an array of hints, not an object. Exact IDs `google/gemini-3.5-flash` and `xiaomi/mimo-v2.5-pro` both passed real model-receipt checks after this correction. Nonexact `xiaomi/mimo-v2.5` routed to the pro model and was correctly blocked. History is now bounded by 48,000 text characters (8,000 per message), instead of ten messages; cross-model recall of both early and recent test facts passed.

The shared ChatCut composer supports @ asset suggestions, removable reference chips, file import/paste and dictation. Storyboard conversations use a distinct account/project namespace. Canvas/model/media snapshots use revision-guarded IndexedDB transactions, read before writes. Success is displayed only after the exact snapshot commits; a conflicting writer is retained as a recovery copy rather than overwriting the winning revision. Media is also committed into the editor's existing asset storage. This is same-browser recovery, not cross-device canvas sync.

## Current host limitation

The verified Anna `video.generate` contract offers `imageUrl` (first frame) but no end-frame parameter. The storyboard assistant explains that limitation instead of silently producing a first-frame-only video or claiming completed start/end-frame support. No fake video models or generated demo nodes are preloaded. Real cloud LLM/image calls require an authorized Anna host and quota. An official local Anna host connected to the real LLM, image and APS services was used for the checks below; no app draft was pushed.

## Dragging composer media to the canvas

Composer attachments and asset references can be dragged onto the Storyboard canvas without removing them from the conversation. The drop position is converted through the current canvas pan and zoom. Existing cards for the same asset move to that location instead of duplicating; otherwise a reference card is created. This is a local project edit and does not invoke generation. The shared ChatCut drag callback is opt-in, preserving other workspaces' pointer behavior.

Storyboard ports are interactive controls: drag an output to an input, or activate the output and then the target input. Pending cables show the source and available targets; Escape or a canvas selection cancels. Connections update canonical `parentIds`, persist with the project, and reject self-links and cycles. Imported reference cards participate in this same connection graph. Editing dependencies does not regenerate existing media automatically.

## Shared manual and agent workflow contract

`src/lib/storyboardGraph.js` owns the node and dependency rules for both ports and tools. Reference nodes are imported image sources. Character drafts accept reference/character parents; environment drafts accept reference/environment parents; boards accept reference, character, environment, and board parents. Sources do not have inputs. Video/audio imports do not expose unsupported image-generation outputs. Each target accepts up to eight image dependencies, with self-links and cycles rejected. Edges describe generation inputs, not timeline order.

Dragging an output into empty space opens only valid successor types, and choosing one creates an editable draft plus its edge without generation. Input ports can be dragged into empty space to create a valid upstream draft or import a reference image. The canvas plus control also creates independent text-prompt drafts. Connected inputs can be disconnected individually. Empty prompt or incomplete/stale upstream images disable generation. An image node may otherwise run from text alone; a board does not artificially require both a character and an environment.

The manual Generate action and the agent's `storyboard_image` share the same Anna image transport and canonical upstream asset resolution. Generated media is committed before attaching it to its original draft; if the prompt, dependencies, or upstream result changed, current edits are preserved and the generated asset remains in My assets. Prompt/dependency changes mark existing generated results out of date. Generation is explicit and uses account quota; no automatic topological execution or automatic paid retry occurs. `storyboard_node` creates or edits drafts, `storyboard_link` connects/disconnects, and `storyboard_image` may fill an inspected draft by nodeId. Anna's currently unavailable end-frame video transport is not presented as an executable successor.

Cable gestures retain an explicit pointer ID and source/target identity until a document-capture `pointerup` handler completes them. Finishing never depends on `hasPointerCapture()` still being true: an early capture release must still open the compatible-node menu. The gesture is cleared before later hover/click events; cancel, Escape, blur and workspace teardown clear pending movement. This also prevents a trailing hover from reverting a completed menu to an unfinished cable.

## Explicit image references in node prompts

Each connected input shows its actual filename and thumbnail, with separate Preview and Disconnect actions. Typing `@` in a node prompt offers only its connected, available image inputs, with thumbnail previews and filename search. Arrow keys, Enter/Tab, Escape and IME composition are handled locally. A selected mention stores the source node ID independently of its human-readable token; duplicate filenames get distinct tokens. Mention mappings persist with the node. Removing an input does not silently rewrite the prompt: an active mention of that disconnected input blocks generation until reconnected or removed.

The shared generation transport resolves mentions by node ID and supplies an explicit token-to-attachment mapping after the two internal guides. Reordering input edges updates the attachment ordinals without rebinding the token to a different image. Mention metadata contributes to the generation signature, while nodes with no mentions retain the previous signature format.

## Image branching and first-frame video, 2026-10-19

Single-image reference, character, environment, generic image and extracted-panel nodes can branch to editable image or video drafts. A generic image accepts up to eight image inputs and uses the selected real image model, without the specialized reference-sheet guides. Its output can feed another image or video. Manual connections and agent tools use the same DAG validation; video accepts exactly one image input and has no output. A composite board cannot feed video directly.

A completed 4×4 board exposes sixteen thumbnail buttons. Selecting one locally crops that equal-size cell into a new image asset and dependent panel node; it does not submit generation. The grid is uniform, not semantic panel detection, so users must preview crops when generated borders or layouts vary. The `storyboard_panel` tool provides the same crop operation to the agent. Changing an upstream board invalidates dependent panels through the shared recursive readiness checks.

Video submits one real reference blob through the existing Anna first-frame API, using host-default model, duration and resolution, clearly described beside its prompt. No end-frame field or selectable video model is invented. Returned job IDs are retained on the draft with the exact input signature; another explicit click queries that job instead of resubmitting. Changed inputs cannot reuse a pending receipt. Completed video bytes are downloaded into My assets and attached to the same node, without timeline insertion. Refresh recovery relies on the normal committed browser snapshot; a request interrupted before receiving a job ID cannot be recovered by ID.

## Canvas trackpad ownership, 2026-10-19

Infinite Canvas and Storyboard share `useCanvasGestures`. Non-passive canvas-local capture listeners cancel native wheel zoom/pan defaults before handling Chromium Ctrl+wheel pinch or WebKit gesture events. Plain two-axis wheel pans the canvas; zoom preserves the world point under the pointer, while explicit zoom buttons retain their centered behavior. WebKit's accompanying wheel events are suppressed during its gesture sequence so it is not applied twice. Control surfaces retain ordinary native scrolling and do not forward pinch to browser zoom. Canvas overscroll containment prevents scroll chaining. Listeners are removed on unmount; there is no document-wide browser-zoom lock. Touchscreen two-pointer manipulation is not added by this trackpad fix.
