# Anna speech synthesis and dictation

The Anna edition adds Local voice / Anna voice inside the existing synthesis tab. Local synthesis remains available. Anna reads granted TTS models, preferred model, voice IDs, default voice and character limits from `llm.catalog({serviceType:'tts'})`. `audio.speak` uses the selected real model/voice and requests inline MP3; an HTTPS result URL is downloaded if the host falls back to URL delivery. Downloads are bounded to 30 MiB, omit credentials and reject redirects. The editor decodes the real bytes before committing a generated voiceover to My assets. Nothing is automatically inserted into the timeline. There is no fabricated preview or provider fallback. Stop waiting discards the result but cannot cancel an already submitted host synthesis call or its billing; requests are never retried automatically.

Anna ChatCut dictation uses SDK 0.21.0 `audio.mic` (16 kHz PCM16) and `audio.session({llm:'none'})`. It performs no LLM turn, TTS playback, or message submission. Partial text is transient; final ASR sentences enter the existing draft. Stop mutes and releases the microphone immediately, flushes ASR, and closes after the flushed event. A 12-second finalization timeout closes with an error without treating partial words as final. Startup, recording and remote session lifetimes are bounded. Unmount, language changes, hidden pages, aborts, host errors and failed startup stop the mic; late results are ignored. The ordinary web edition retains its existing Web Speech input.

Manifest declarations: `llm.catalog`, `audio.speak`, `audio.transcribe`, `audio.session`. No agent-session permission is requested. User grants are separate: speech generation needs audio.enabled + speak; the current host requires enabled + speak + transcribe for realtime sessions even when llm is none. The microphone also needs the host iframe policy and an explicit browser permission. An older host without the SDK relay must fail honestly, never simulate recognition.

Validation: production build and schema validation; isolated mocked contract checks cover catalog filtering, inline audio bytes, ASR-only session config, flush, cleanup, late events and all 13 UI languages. These do not establish real provider synthesis quality or microphone recognition. At implementation time, the installed draft grant contained transcribe but no speak; live validation must wait for that user grant and a microphone-enabled Anna host window.

Avatar assets (built-in image generation, 2026-10-17): `public/assets/voice-avatars/anna-{jade,amber,violet}.png`.
Prompt set: one centered anime-inspired gender-neutral futuristic fox-spirit voice companion with subtle headphones, dark circular studio background, clear at 48 px, no text or logos; jade/cyan, amber/midnight-blue, and violet/silver palettes respectively. These are fictional visual identifiers, never claims about the real speaker identity or gender. The three assets are assigned by stable model/voice hash, including across catalog reorderings. Cloud cards use only the preferred catalog model (or the first available model if none is preferred), respecting the user's host model setting without another model selector.

Automatic captions in the Smart inspector, audio/source properties, caption empty state, desktop clip menus and mobile clip actions use the same Anna file-STT chain in this edition. ChatCut `timeline_ai_process(kind:captions)` uses that chain too; its receipt retains explicit audio/visual ownership. The ordinary web edition keeps local Whisper and browser file speech. Source trim, fixed speed and source-time speed curves map transcription ranges to timeline time; reverse speech is rejected. User-requested microphone dictation remains the separate Anna ASR-only realtime session. File transcription currently returns text only, so subtitle timing is estimated from measured speech boundaries, not provider word timestamps. No automatic retry or fabricated recognition fallback is used.

### Anna voice auditions (2026-10-17)
Anna cards play pre-recorded, exact-voice-ID samples published by Alibaba Cloud; clicking a card never calls `audio.speak`. `src/lib/annaVoiceSamples.js` records the verified mappings from the official [Qwen-Audio-TTS voice list](https://www.alibabacloud.com/help/en/model-studio/qwen-audio-tts-voice-list) and [Qwen-TTS voice list](https://www.alibabacloud.com/help/en/model-studio/qwen-tts-voice-list). Audio stays on the provider's HTTPS host, uses anonymous CORS playback, and is not copied into product assets. Unmapped voices remain disabled until a real matching sample is supplied; no fallback speaker is substituted. One hidden audio element is shared by the Anna cards. A card click selects the voice, pauses the previous sample, sets the exact source, loads it and calls play synchronously in the user gesture. Replaying a selected card restarts its sample. Playback failures appear only in the selected card subtitle. The official sample host is explicitly allowed in the Anna bundle origins and media CSP; HTTP availability alone is not a browser playback check. Samples never enter My assets or the timeline.

## Editor voice assistant

The Anna top bar includes a phone control. Clicking it expands an inline waveform strip in the header rather than a popover over the video. It starts connecting immediately; no second Start call button is required. The strip retains localized status, latest transcript/reply, mute, interrupt and hang-up controls. Media-generation confirmation also stays inline. Waveform levels come from captured microphone float samples and PCM TTS chunks, not a decorative speaking animation; reduced-motion sessions disable height transitions. On narrow screens the header reserves its own second row without covering the preview. It starts a host-owned `audio.session({llm: "none"})` with the account's realtime ASR/TTS preferences, not a separately selected local model. Final utterances use the existing ChatCut tool loop and its semantic preview, stale-state check and apply path. `timeline_ui_inspect` reports current panel, selection and the actual tool catalog; `timeline_ui_navigate` opens only enumerated editor panels. Opening export settings never exports or publishes a video. This is the editor's existing Skill/tool contract, not arbitrary operating-system skill execution.

The first version is half-duplex: microphone frames are gated while an editor command is running or its response is speaking. Mute, Interrupt and End call are explicit controls. Interrupt cancels the pending local tool loop and stops speech; it does not undo an edit already committed or cancel a cloud request already submitted. Hiding the document, changing language/project, or unmounting closes the mic, player and host session. The requested lifetime is ten minutes, subject to the host's cap. Audio and necessary command/project context are sent to Anna under the account's existing grants and billing.

Media-generation tools require a visible confirmation before execution. Confirmation reruns the instruction against the current project. Audio replacement/narration keeps the existing listen-and-review requirement. Read-only capability questions and panel navigation do not generate media. No automatic retries after provider failures. Full-duplex voice barge-in and voice-triggered publishing are not implemented.

### Automatic-caption targets

Smart → Auto captions defaults to All visual clips whenever the timeline has video clips. Timeline selection does not override that default or a manual source choice. Users may explicitly choose one video/audio clip; its insertion offset defaults to its timeline start. A manual source choice remains selected after committing its captions. With multiple main-visual videos, All visual clips processes each video separately using its own source trim, speed mapping and timeline start, retains per-clip visual ownership, and appends captions without deleting existing captions. Batch results commit together only if the original targets remain unchanged and the caption track remains unlocked. Silence-only clips may be skipped; cancellation or provider errors do not commit a partial batch.

## Low-latency voice intents

Exact greetings, hearing checks and thanks use localized local replies without a model request. Exact Chinese/English panel navigation and play/pause/undo/redo commands inspect the live UI then use the existing validated UI adapter; no media-edit logic is duplicated. Negation, compound or ambiguous instructions and all media editing/generation fall back to ChatCut. Voice-mode ChatCut responses request one or two plain spoken sentences while retaining the same inspections, semantic preview, apply rules and generation/listening confirmations. No speculative execution happens on partial ASR text.

The host API remains streaming ASR → app command/model handling → streaming TTS, not an app-selected native speech-to-speech model. Complex commands still include ASR finalization, model/tool rounds and TTS latency. The app does not claim full-duplex barge-in: its serialized microphone gating and explicit interrupt control remain intact.
