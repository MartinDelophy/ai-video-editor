# Anna 当前工程自动保存与恢复 · 2026-09-15

本轮补充 Anna 当前工程的浏览器本地自动保存与重新打开恢复能力。恢复范围为**同一浏览器、同一 Anna 账号**；工程和素材不会因此自动上传到 Anna，也不是跨设备云同步。本文记录实现范围与验收边界。本地验证及 Anna 生产容器的 r15 样本验收已通过。随后冻结为 alpha.4 / 775 并替换审核候选，目前 pending_review、未公开发布；详见 [送审记录](anna-review-submission-20260915.md)。

## 保存位置与账号范围

| 数据 | 保存位置 | 用途与边界 |
| --- | --- | --- |
| 当前工程及其媒体 Blob | 浏览器 IndexedDB | 保存可恢复的本机工作内容；重新打开后从本机读取，并重新创建媒体 URL。其它浏览器、浏览器配置或设备没有这份本机数据。 |
| 随机 namespace 及格式版本 | Anna scoped KV | 为同一 Anna 账号定位本应用的本机记录，只保存随机标识，不保存工程、媒体或编辑内容。取得相同 namespace 不会把本机素材同步到其它设备。 |
| 显式云工程保存 | 既有 Anna 云文件功能 | 仍是单独的用户操作，与本轮本机自动保存分开；不能把本机“已保存”解释为云端备份。 |

IndexedDB 的当前记录、修订检查与旧记录保留在同一写事务内完成。只有事务 `oncomplete` 后，保存方法才返回成功并允许界面显示“已自动保存到此浏览器”；单个写请求成功、保存已排队或媒体准备开始都不算保存完成。

## 自动恢复与冲突处理

重新打开时，先解析账号对应的 namespace 并读取上次记录，再决定恢复或开始后续自动保存。不会用刚启动的空白编辑器抢先覆盖上次已保存的工程。保存期间出现的新编辑继续进入下一次保存，不以先前快照的提交结果冒称最新编辑已保存。

保存失败时，事务回滚保留已有持久化工程，当前编辑仍保留在界面中；状态显示未完成并提供“重试”。读取、素材准备或恢复失败也不能默默替换当前工程。

恢复等待期间检测到新编辑，或保存时检测到记录修订冲突，应暂停自动覆盖，显示“检测到新编辑，未覆盖当前工程”，由用户选择“恢复上次工作”或“保留当前工作”。两个选择均通过现有保存与恢复逻辑处理，不把冲突当作已成功保存。

顶栏状态区直接提供等待、检查、恢复、就绪、保存中、已保存、错误及冲突状态。已保存状态可附本机保存时间；紧凑提示说明同一浏览器和账号的范围，错误不展示原始内部异常。状态与操作文案覆盖 13 种界面语言。

## 恢复限制

恢复依赖仍然存在且已完整提交的浏览器记录。**浏览器清理站点数据、隐私模式结束、存储被回收或保存尚未完成时，无法保证恢复。** 关闭页面前触发的异步保存也没有完成保证；“正在保存”不等于“已保存”。需要独立副本时，应使用现有的显式工程备份或云保存操作。

同一账号的 namespace 只负责记录定位，不提供跨浏览器或跨设备的工程传输。登录状态、scoped KV 或本机存储不可用时应显示实际失败状态，不能改用另一个账号的记录或给出成功提示。
