# 3D blockout workspace (prototype)

Workflow → 3D Blockout opens an isolated, lazy-loaded Three.js scene workspace. The original video timeline is not changed. Scene objects, walking destinations, camera shot ranges and duration are serialized as one versioned JSON document. Changes persist per project in the current browser; this prototype does not claim cloud or cross-device scene sync. The Export dropdown downloads either that JSON document or a real 1280×720 WebM camera-view video, with progress and cancellation. Video export is disabled for an empty scene.

`src/lib/blockoutScene.js` owns the scene command contract and validation. `applyBlockoutEdits(scene, operations)` returns a new snapshot without mutating its input. Supported operations: update an existing object's transform or walking destination; add a character/prop; change duration; edit a shot camera position/target. Arbitrary code, external assets and unknown object IDs are rejected. Mouse/property controls use the same command engine as Anna proposals.

Anna chat sends the current scene metadata and a single scene-edit catalog to the existing host completion service. Proposed changes are validated, shown for review, then applied as one undoable edit only if the inspected scene still matches. Cancellation stops local waiting. Remote planning needs a working Anna host session; offline manual editing remains usable. This is not a full Blender implementation or an unrestricted modeling agent.

New projects start empty, showing only an editor grid. No classroom, characters or example chapters are preloaded. A camera rig is prepared for later preview/export; the camera and top-down insets remain hidden until scene objects exist. Earlier prototype data remains under its prior storage key rather than being deleted. Playback is generated live from scene data. Character voice is explicitly marked as future work. Multi-chapter authoring, voice binding, imported meshes, rich keyframe editing, collision/IK, imported media and full video-timeline integration are not implemented yet.

Character actions and camera shots now share the playback clock with a following script carousel. Clicking an action, shot or script segment seeks to its start. Script lines can be edited inline with explicit start/end times; initial even timing is an editable estimate, not speech alignment. The command engine validates `motion`, `shot`, and `script.replace` operations, rejects overlapping ranges, and scales all timed content together on duration changes. Preview and video export use the same actor pose and camera-cut helpers.

The dialogue pane now uses the shared `ChatCut` component rather than a separate composer. It shares session history, account/project-scoped conversation drafts, Enter/Shift+Enter and IME handling, Markdown messages, optional dictation, and object-reference pills. `BlockoutChat` adapts the scene command catalog and renders reviewed scene proposals without exposing unsupported image/remotion commands or media-import actions. Applying a proposal still checks the inspected snapshot; cancellation and conversation changes leave the scene intact. The original scene storage key and existing scenes remain unchanged.

All three workflow entries use `WorkflowWorkspace`: a visible loading state, a local React error boundary, Retry with a new lazy component, and Back to editor without unmounting the main editor. The Anna builder retains the current plus four previous hashed JS/CSS/WASM dependency graphs across mutable draft updates (`anna-runtime-history.json`), while keeping the existing network-only executable service-worker policy. `ANNA_RUNTIME_COMPAT_BUNDLES` may supply a JSON list of prior bundle directories when bootstrapping a deployment from older artifacts. Compatibility is bounded; much older tabs may need reopening.
