## 默认云端保存架构

- 启动先读取账号级云端指针，存在时恢复云端工程。云端读取失败不能被当成空账号，也不能静默恢复旧的本机副本。恢复期间的新编辑继续受冲突保护，不能被异步读取或重试覆盖；新工程默认进入云端自动保存流程，不依赖手动开启。
- 远端确认为空时，可尝试读取历史本机工程用于迁移。旧 IndexedDB 或 namespace 读取失败只产生独立的迁移提示，不将其伪装成已恢复，也不阻止当前新编辑使用云端保存。提示建议导入此前导出的工程备份，并与真实云端保存/错误状态并列；不得隐藏云端自身的失败。
- `annaCloudSessionStorage` 将工程快照编码为有类型的对象图，保留 File/Blob、二进制视图、共享引用、循环、Map、Set、Date 等实际工程数据。素材使用流式 SHA-256 校验和内容去重，写入不可变文件；快照清单也使用新的不可变文件。已加载素材的引用用于后续去重，单纯元数据编辑无需重复上传原始媒体。
- 媒体和清单上传、校验完成后，才更新 Anna scoped KV 的当前工程指针。已有指针使用读取时的 etag 作为 CAS 条件；保存失败不会偷偷接纳另一窗口的新基线。指针记录当前和上一份清单，失败或竞争产生的文件不自动删除。
- 若请求超时但实际已提交，重试只能确认自己那份文件和 revision，不能把无关新工程当作成功；相同待提交快照可复用已经上传的文件。只有云端提交成功或精确回读确认后才显示已保存。
- 云端读写和恢复直接处理内存中的工程与媒体，不依赖 IndexedDB 保存成功，也不再写一份完整本机副本。本机旧记录仍保留；本机配额耗尽不阻断已确认的云端提交。云端自身的网络、权限和配额限制仍会明确报错。

**首次创建边界：** Anna 当前没有原子的 create-if-absent。首次写入前检查、写入后回读能发现当时可见的竞争，但后到的另一个首次写入者仍可能替换指针；两份不可变快照文件都会保留。因此已有行的 CAS 保护不等于首次创建也具有原子性，不宣称完整消除了跨窗口或跨浏览器首次创建竞态。

## r17 可复现竞态及本轮修正

仓库外的 `/tmp/anna-session-r17-races-20260915.mjs` 使用 r17 hook/resolver 源码和受控存储时序复现了以下行为。这些复现说明代码路径确实存在问题，不表示它们就是用户这次生产配额错误的原因。

| 场景 | 既有行为与本轮处理 |
| --- | --- |
| 无编辑重开 | 恢复后未建立已保存指纹，打开两个窗口也会依次增加 revision，使第一个窗口之后的真实编辑进入冲突。本轮在恢复状态完成 React 提交后记录指纹，无编辑重开不再额外保存；提交后的新编辑仍作为未保存内容处理 |
| 失败后的重试 | 原 Retry 走显式恢复路径，启动失败后新建的工作可能被旧工程替换。本轮保留首次读取的编辑边界和恢复目标，重试发现新编辑或 revision 变化时进入冲突，仅显式“恢复上次工作”允许替换 |
| 显式恢复保护 | 替换前保存当前完整工作；重试记住已经完成的保护，不重复建立备份。恢复成功后再持久化恢复目标，保留此前工作作为上一版 |
| 首次 namespace 创建 | 受控跨浏览器并发可使两个首次打开获得不同 namespace。本轮没有修改 resolver，未宣称解决此项风险；也未将其认定为生产 quota 错误的原因 |

旧本机模式的工程和素材保存在 IndexedDB，旧 namespace KV 只用于本机隔离，历史恢复依赖同一浏览器、同一 Anna 账号。新的默认流程将工程及媒体保存到 Anna 账号文件存储，云端版本指针由另一个 scoped KV 键维护。旧记录不会被视为已上传；云端保存仍以提交确认为准，未完成保存的内容不能保证恢复。
